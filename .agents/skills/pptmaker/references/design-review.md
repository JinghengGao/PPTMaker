# 逐页复核表达效果

本指南由 PPTMaker 独立编写，设计研究背景见 [项目 Skills 说明](../../../../docs/SKILLS.md#设计研究参考)。它补充现有技术验收，不替代浏览器检查、Export、Check 或成品复核。

用于实际视觉验收。只报告看过的页面和运行过的检查；用户只要求检查时不自行修改，局部修改时只处理授权范围。

## 对照本页任务查看画面

先读 brief.md 中的页面任务与依据，再查看实际渲染：

- **观点**：读者能否从可见内容知道本页在回答什么；标题或结论是否超出本页证据。
- **关系**：流程、连接、分组、比较或运算是否能读懂，图中有没有来源未说明的关系。
- **证据**：图、表、符号、数据与说明是否对应；必要条件、来源和限制是否保留。
- **阅读**：重点是否突出，文字、图内标签、公式与图注是否可辨；是否存在遮挡、过密或阅读顺序不清。

信息可以由文字完成，不因缺少图标或复杂图形判失败。审美上的其他可行选择也不自动构成缺陷。

## 专门检查容易漏掉的区域

放大核对图内小字、箭头端点、坐标、图例、裁切边缘及公式上下标。自动检查可能只观察容器，不能据此推断 SVG 内文字和叠加对象均正常。确认实际字体与字号，避免缩放或样式覆盖造成失真。

比较同类页面的名称、颜色、符号、单位、精度与尺度；不要让相同形式在不同页表达不同含义。来源说明应能读到，并与其支持的对象保持清楚联系。

遇到无法加载或编译失败，先记录技术阻塞；恢复后再完成视觉复核，不能把未显示的页面当作已检查。区分技术阻塞修复与可视稿的设计修改，保留真实修正过程。

## 修正与记录

集中记录当前范围内的问题，再针对原因修正。事实错漏、核心关系不清或页面不可读，需要优先处理；轻微间距和偏好差异与这些问题分开。修改后复查受影响页及相关联页面，不为统一外观重做未授权内容。

在现有 QA.md 中分别说明技术检查、设计观察、实际修改和未验证项；必要时标明页码及对象。只有实际进行对照时才说明哪一版更好，不以规则文件增多或主观印象声称普遍提升百分比。

最后打开或渲染 PDF/PPTX，核对文字、关系、图像、公式与数据是否保持。网页画面、PDF 和 PowerPoint 原生画面可能不同；有差异时注明具体页和格式，以及对象的实际可编辑范围。截图与报告继续只作临时验收。
