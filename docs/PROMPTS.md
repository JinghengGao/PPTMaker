# 给 Agent 的任务提示词

在仓库根目录打开能读写文件、执行 PowerShell 并使用本地浏览器的 Agent。先完成 README 的环境安装；也可以让 Agent 按 README 检查并安装缺少的项目依赖。Skills 是操作说明，不会自行运行模型或提供浏览器权限。

支持项目 Skill 的 Codex 可直接使用 `$pptmaker`。其他 Agent 或未发现 Skill 时，把提示词第一行替换为：`先读 AGENTS.md、README.md 和 .agents/skills/pptmaker/SKILL.md，并按该流程完成以下任务。`

替换方括号中的任务信息，不要把示例参数当成真实数据。材料路径填写自己机器上的实际位置，不把私人材料写进公共文档。

## 1. 从资料制作完整演示

```text
使用 $pptmaker，在当前 PPTMaker 工作区制作并交付一套演示。

主题：[要介绍的问题或工作]
受众与目的：[受众已有知识、希望他们理解或决定什么]
Deck ID：[例如 my-talk]
主题样式：[default / mc / nku，未指定时使用 default]
时长与页数：[例如约 10 分钟、8 页，含封面与结尾]
输出版本：[例如 1.0.0]
资料：[本地文件/目录，以及可使用的网址]
必须覆盖：[关键问题、方法、证据、局限或结论]
其他要求：[是否需要讲稿、语言、必须保留的图表等]

先核对资料，把主线、逐页提纲和出处写入 brief.md。仅对影响事实或交付的缺项集中提问，排版选择可自行决定。给出简短主线说明后，在已授权范围内继续完成制作、逐页预览、修正、导出和检查，不停在计划阶段。

不要编造数据、引用或作者身份；缺少依据的内容明确标注待确认。以原生文字、表格内容和有意义的图示组织页面，不把整页图片当作可编辑 PPT。保留来源与必要限制。最终交付源稿、PDF、可编辑 PPTX，并报告真实验收结果和未验证项。
```

如果只想先审阅提纲，在末尾加：`本轮只交付 brief.md 中的逐页提纲，先不制作页面或导出。`

## 2. 修改已有演示

```text
使用 $pptmaker 修改已有 deck：[Deck ID]。
目标版本：[X.Y.Z]
修改范围：[指定页码或标题，以及要解决的问题]
可使用资料：[路径/网址]
需要保留：[关键结论、图表、视觉风格或指定文字]

先读现有 brief.md、slides.md、QA.md 和 Git 状态，确认目标页。保留其他页面与作品，只做支撑本次目标的修改；不默认重做整套设计或更换主题。事实变动记录来源，样式修改检查是否影响共享主题。

完成后逐页复核受影响内容，导出指定版本的 PDF 与可编辑 PPTX，保留其他版本，在 QA.md 记录结果与限制。
```

## 3. 学习参考并形成可复用主题

```text
使用 $pptmaker，根据参考材料创建一个新的可复用 Slidev 示例主题。
参考文件：[真实路径]
新示例 ID：[避免 demo、mc、nku 和已有 ID]
参考中要保留：[字体层级、配色、布局或指定品牌元素]
需要替换或排除：[作者身份、私人材料、无权分发的素材等]
示例页数与输出版本：[要求，版本 X.Y.Z]

逐页观察参考，记录字体、配色、布局的页码依据；无法确认的属性明确标注，不声称像素完全一致。按 docs/WORKFLOW.md 创建 slides.md、manifest.json、STYLE-GUIDE.md、theme/ 与必要素材，给出通用占位内容，示例数据明确标注。

品牌和主题样式留在新示例内部；只在确有中性复用需求时调整 shared/，并回归受影响示例。不要修改官方 demo。完成预览、逐页对照与 PDF/PPTX 检查，记录真实验证范围。参考原件只读，公开授权未经确认的内容不自动提交或上传。
```

这类任务包含主题实现，区别于只用现有 mc/nku 制作一套新作品；只想沿用样式时使用第 1 条。

## 4. 补充讲稿与排练

```text
使用 $pptmaker 和 $slidev-presenter-mode，为 [Deck ID] 补充讲稿。
受众：[背景]
总时长：[分钟数]
讲述目的与重点：[要求]
输出范围：[只补讲稿 / 同时优化页面并导出 X.Y.Z]

读取现有源稿，为每页写有依据的讲述顺序、必要解释与自然衔接，放在该页末尾的 HTML 注释中。时间分配是预计值，不编造真实排练结果。关键限制仍须在页面可见。

启动本地预览，检查演讲者页面的页码、讲稿和翻页；没有实际使用投影或录制时不要声称已验证。默认不启用远程访问、摄像头或录屏。
```

## 5. 验收或继续未完成的任务

```text
使用 $pptmaker 检查并继续 deck：[Deck ID]，目标版本：[X.Y.Z]。
本轮范围：[只检查并报告 / 修正发现的问题后重新导出]

先读 brief.md、slides.md、QA.md 和已有成品，判断已完成内容与缺口；不要重新创建 deck 或重复已完成步骤。逐页核查事实与出处、图片、公式、字体、布局及控制台，再检查 PDF/PPTX 页数、原生文本与实际渲染。

只报告有证据的结果：自动检查、视觉复核、PowerPoint 原生渲染分别记录；缺失能力明确写未验证。未经我明确接受，不使用 AllowKnownToolchainIssues 放行错误。检查失败不覆盖旧成品；临时截图和报告在结束后删除，结论简记到 QA.md。
```

资料不足、环境缺失或导出失败时，Agent 应保留已有成果并说明具体缺口。它不应为让检查变绿而删结论、忽略错误、冒充已看过截图或修改官方原稿。
